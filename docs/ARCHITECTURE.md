# Архитектура Zentrix

Документ описывает, как устроено приложение, где проходят границы потоков и
почему интеграция с движками не открывает дополнительные окна.

## 1. Слои

```
┌──────────────────────────────────────────────────────────────┐
│ UI (PySide6)                                                 │
│  main_window · pages/ · widgets · theme · overlays · tray    │
├──────────────────────────────────────────────────────────────┤
│ AppContext                                                   │
│  общие настройки · звук · движки · монитор · тема · shutdown │
├──────────────────────────────────────────────────────────────┤
│ Движки и сервисы                                             │
│  engines/zapret · engines/happ · engines/hiddify · cores     │
│  netmon · blocking_check · updater · cleaner · net           │
├──────────────────────────────────────────────────────────────┤
│ Системный слой                                               │
│  winapi (WinDivert/прокси/топ-процессы) · paths · logger     │
└──────────────────────────────────────────────────────────────┘
```

`src/constants.py` и `src/paths.py` не тянут тяжёлые зависимости: они
загружаются первыми и должны оставаться дешёвыми.

## 2. Жизненный цикл

1. `src/main.py` настраивает логирование, DPI, `QApplication` и стиль Fusion.
2. Захватывается именованный мьютекс `Local\Zentrix.SingleInstance.v1`.
   Второй процесс отправляет `show` в `QLocalServer` и завершается.
3. Создаются каталоги `%APPDATA%\Zentrix`, `SoundManager` и `AppContext`.
4. `MainWindow` строит каркас: title bar, боковую навигацию, `QStackedWidget`,
   фон и трей. Страницы **не создаются** — только кнопки навигации.
5. Окно показывается. Только после первого кадра (`QTimer.singleShot`)
   запускаются стартовый звук, прогрев кэша звуков, автоочистка и
   `autostart_engines`.
6. При переходе на вкладку `MainWindow.navigate()` импортирует модуль страницы
   через `importlib`, создаёт её, кладёт в `ctx.pages` и вызывает `on_show()`.
   При уходе вызывается `on_hide()` — страницы останавливают таймеры.
7. При выходе `AppContext.shutdown()` останавливает монитор, сбрасывает
   системный прокси (если он был включён Zentrix), вызывает `cleanup()` у всех
   движков и сохраняет настройки.

## 3. Потоки

| Поток | Что делает | Как завершается |
|---|---|---|
| GUI (main) | Отрисовка, события Qt, лёгкие операции | `app.exec()` |
| `TrafficMonitor` (QThread) | psutil-счётчики, TCP-таблица, процессы | `stop()` + `wait()` |
| `Task` (QThreadPool) | Сеть, проверки, обновления, очистка | `QRunnable` + сигналы |
| `sound-warmup` | Генерация WAV в кэш | daemon |
| `auto-clean` | Безопасная очистка при старте | daemon |
| `stale-*` | Поиск «осиротевших» PID движков | daemon |
| Движки | `QProcess` для `winws.exe` / `xray.exe` / `sing-box.exe` | `cleanup()` |

Правило: любой сетевой или дисковый вызов, который может занять больше
нескольких миллисекунд, не выполняется в GUI-потоке. Для страниц используется
`run_task()` из `src/ui/workers.py`, результат приходит сигналом в GUI-поток.

Графики и логи обновляются не чаще 1 раза в секунду. Страница мониторинга
останавливает таймер в `on_hide()`.

## 4. Окно и оформление

- Окно frameless (`Qt.FramelessWindowHint`), собственный title bar с
  перетаскиванием и кнопками. Изменение размера — через нативный
  `WM_NCHITTEST` в `winapi`.
- `BackgroundWidget` рисует статический градиент и, если включено видео,
  кадры `QVideoSink`. Затемнение и виньетка применяются только поверх
  активного видеокадра, чтобы не «мылить» градиент.
- `theme.Palette` собирается из секции `appearance`. `theme.qss()` генерирует
  единый stylesheet; `theme.qcolor()` понимает `#rgb`, `#rrggbb`,
  `#aarrggbb` и alpha.
- Иконки — SVG с корневым `stroke="#EAF0FF"`; `svg_pixmap()` перекрашивает
  `#EAF0FF` и `currentColor` под текущую палитру.
- Тост-уведомления и модальные панели — внутри окна (`Overlay`), без нативных
  диалогов, чтобы не плодить окна.
- Светлая/тёмная темы, акцент, радиус, прозрачность карточек и размер шрифта
  меняются на лету. Перерисовка темы дебаунсится на 120 мс.

## 5. Движки

### Zapret (`src/engines/zapret.py`)

- Сканирует `engines/zapret/*.bat`.
- Читает файл в `utf-8-sig`, `cp866`, `cp1251` (порядок важен для русских
  комментариев upstream).
- Извлекает `set`-переменные, раскрывает `%VAR%`, `%~dp0`, `!VAR!`.
- Собирает argv для `bin\winws.exe` и запускает его напрямую через `QProcess`
  с `CREATE_NO_WINDOW`.
- Игровой фильтр: если выключен, подставляется порт `12`, чтобы не блокировать
  игры; если включён — используется `utils/game_filter.enabled` и штатные
  параметры upstream.
- stdout/stderr читаются и показываются в логе страницы. При остановке
  процесс завершается, дочерние процессы не остаются висеть.
- Обновление сохраняет пользовательские `lists/` и флаг игрового фильтра.

### Happ (`src/engines/happ_engine.py`, `links.py`, `cores.py`, `proxy_engine.py`)

- Разбирает share-ссылки `vless://`, `vmess://`, `trojan://`, `ss://`.
- Генерирует JSON-конфиг Xray: inbound SOCKS/HTTP на localhost, outbound —
  выбранный сервер (TLS/Reality/WS/gRPC и т.д.).
- Скачивает `xray.exe` с официального релиза XTLS/Xray-core по требованию.
- Запускает ядро скрыто; системный прокси включается через WinINET при
  необходимости.
- Оригинальный GUI Happ не запускается и не требуется.

### Hiddify (`src/engines/hiddify_engine.py`)

- Та же схема на sing-box: share-ссылка → JSON-конфиг → `sing-box.exe`.
- Отдельные порты mixed/API, чтобы Happ и Hiddify могли работать
  одновременно.
- GUI Hiddify не запускается.

## 6. Мониторинг и проверки

`TrafficMonitor` суммирует счётчики адаптеров psutil, читает TCP-таблицу через
`GetExtendedTcpTable` и сопоставляет соединения с PID. Скорость считается по
дельте между тиками.

`blocking_check.py` выполняет для каждого сервиса:

1. системный DNS-запрос;
2. DNS-over-HTTPS (Cloudflare) для сравнения — признак подмены DNS;
3. TCP-подключение к 443;
4. TLS ClientHello с нужным SNI и классификацию ответа (успех, RST,
   таймаут, подмена сертификата).

Отчёт агрегируется в `BlockReport` и показывается карточками; результаты
сохраняются в `ctx.block_results` до следующей проверки.

## 7. Настройки и файлы

`Settings` — потокобезопасный in-memory словарь с отложенной записью
(debounce 350 мс) и атомарной заменой файла. Повреждённый JSON переименовывается
в `settings.broken.json`, приложение стартует с дефолтами.

```
%APPDATA%\Zentrix\
  settings.json
  state.json
  logs\zentrix.log
  presets\
  profiles\
  configs\
  cache\sounds\
  downloads\
  temp\
```

`paths.LOCAL_DEFAULTS_FILE` (`settings.local.json` рядом с `.exe` или корнем
репозитория) позволяет разработчику задать локальные пути, не коммитя их.

## 8. Производительность

- Ленивая загрузка страниц: холодный старт не импортирует ни один тяжёлый
  модуль страницы.
- Первый кадр — до запуска фоновых задач.
- Прогрев звуков — в daemon-потоке; стартовый звук играет после появления окна.
- Монитор и логи — ≤1 Гц.
- Тема применяется одним stylesheet, перерисовка дебаунсится.
- Все подпроцессы скрыты, а при выходе принудительно завершаются, поэтому
  повторные запуски не накапливают `winws.exe`/`xray.exe`/`sing-box.exe`.
- Целевой бюджет: ≤1,5 с до интерактивного окна, 60 FPS на анимациях фона.
  На референсной машине окно появляется примерно за 0,4 с после запуска
  packaged-сборки; страницы загружаются при первом переходе.

## 9. Точки расширения

- Новая страница: добавить ключ в `NAV`, `PAGE_MODULES` и модуль в
  `src/ui/pages/`; импорт останется ленивым.
- Новый движок: унаследовать `BaseEngine`, реализовать `start/stop/cleanup`,
  добавить в `AppContext`.
- Новый формат ссылки: расширить `src/engines/links.py` и тесты.
- Новый звук: добавить рецепт в `sound_generator.RECIPES` и событие в
  `constants.SOUND_EVENTS`.
