# Сайт Zentrix (GitHub Pages)

Эта папка — **источник сайта** и одновременно документация проекта.

| Файл | Назначение |
|---|---|
| `index.html` | главная страница лендинга |
| `site.css` | оформление (тёмная тема в стиле приложения) |
| `site.js` | подтягивает актуальную версию и ссылки на файлы релиза через GitHub API |
| `social-preview.png` | картинка 1280×640 для превью ссылки в соцсетях |
| `logo.png` | иконка сайта (favicon) |
| `screenshots/` | скриншоты интерфейса |
| `ARCHITECTURE.md`, `BUILD.md`, `TROUBLESHOOTING.md` | документация проекта (не индексируется как страница) |

## Как включить GitHub Pages

1. Откройте GitHub → репозиторий → **Settings**.
2. В левом меню выберите **Pages**.
3. В блоке **Build and deployment → Source** выберите **Deploy from a branch**.
4. **Branch**: `main`, **Folder**: `/docs`.
5. Нажмите **Save**.
6. Через 1–2 минуты сайт станет доступен:

   ```
   https://w1kscc.github.io/Zentrix/
   ```

## Как обновлять контент

- **Версия и кнопки скачивания** — ничего менять не нужно: `site.js` сам берёт
  `tag_name` и `assets` из `https://api.github.com/repos/w1kscc/Zentrix/releases/latest`.
  После публикации нового релиза страница подхватит его при следующем обновлении.
- **Скриншоты** — замените файлы в `docs/screenshots/` теми же именами.
- **Тексты и блок «Благодарности»** — правятся прямо в `index.html`.
- **Превью для соцсетей** — `docs/social-preview.png`; его же можно загрузить
  в GitHub → Settings репозитория → **Social preview**.

## Если API упрётся в лимит

GitHub API для анонимных запросов даёт 60 запросов в час на IP. Если `site.js`
не получит данные, кнопки останутся с адресом `/releases/latest` — рабочим
в любом случае. Ошибка не видна пользователю.
